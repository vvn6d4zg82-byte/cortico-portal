# 框架契约（P0 定稿）

> 这份文档是框架的**宪法**。它应当能在一杯咖啡的时间内读完。
> 任何让这份文档变长、变复杂的改动，都需要先证明它无法通过插件层解决。

---

## 0. 一句话

**AI 是主角，世界是插件，事件经闸门进池，AI 按批判断。**

框架自己不理解任何领域语义。它只做四件事：**收事件、攒批次、调模型、派工具**。

---

## 1. 四层结构

```
┌─ Core（无语义）───────────────────────────────────┐
│  事件池 · 水位闸门 · 主循环 · 工具派发 · Provider   │
│  它不理解事件是什么意思，也不生成任何语义内容        │
└──────────────────────────────────────────────────┘
        ▲ 事件（Event）              ▼ 工具调用（ToolCall）
┌─ World 插件（可外挂）─────────────────────────────┐
│  订阅外部世界 → 产出事件                           │
│  声明工具     → 执行外部动作 → 回执                 │
│  提供环境描述 → 进 system prompt                   │
│  它不能访问 Memory，也不能调用 Persona              │
└──────────────────────────────────────────────────┘
        ▲ 工具调用                    ▼ 回执
┌─ Persona（语义，可换）─────────────────────────────┐
│  上下文构造 · 认知流程 · 内部提示词 · 记忆使用协议   │
└──────────────────────────────────────────────────┘
        ▲ 记忆工具                    ▼ 检索结果
┌─ Memory（MCP 外挂，可复用别人的）──────────────────┐
│  经验 / 人格 / 索引记忆。Core 视其为不透明内容       │
└──────────────────────────────────────────────────┘
```

**层间唯一合法的通信形式是"语义化契约"**：事件投递与工具描述。
World 与 Persona **不互相 import**，不调用对方的程序接口。

## 2. 核心不变量（改这些 = 改框架）

| # | 不变量 | 违反后果 |
|---|---|---|
| **I1** | **原始高频流永不进闸门。** 插件必须在源头降采样，只有状态跃迁才产生事件 | 事件池被 `/scan` 10Hz 淹没，模型被无意义批次空转 |
| **I2** | **Core 不含语义。** 它不解释事件内容，不生成判断，不做启发式推论 | 框架退化成一个写死的业务系统 |
| **I3** | **模型永不直连执行。** 进入执行层的只有工具调用，且必过安全闸 | 模型幻觉直接作用于物理世界 |
| **I4** | **事件可核验。** 每个事件带 `source + seq + ts`，不可核验的事件进不了池 | 无法对账，AI 在幻觉上做判断 |
| **I5** | **记忆不塞 prompt。** prompt 只放当前世界描述 + 人格内核 + 工作记忆 | 上下文膨胀，人格漂移，失忆 |
| **I6** | **水位决定投递，不决定内容。** 闸门只控制"什么时候给模型看"，不删改事件 | 机械层篡改认知（违反"诚实的认知论"） |
| **I7** | **插件失败隔离。** 一个 World 构造/启动失败不影响其他 World | 单点故障拖垮整个 agent |

## 3. 事件契约

```ts
interface EventEnvelope {
  readonly cursor: number;        // 全局单调游标（Core 分配，跨重启不重置）
  readonly run: string;           // 运行标识（用于分片与回放）
  readonly type: string;          // 事件类型（World 自定，如 'qq.message'）
  readonly ts: number;            // 事件发生时刻（毫秒）
  readonly source: string;        // 哪个 World 产出的
  readonly origin: 'external' | 'internal';  // 外部世界 vs 系统内部通知
  readonly text: string;          // 人话正文（由生产方提供，Core 不加工）
  readonly meta?: Record<string, unknown>;   // 结构化附加信息
  readonly ephemeral?: boolean;   // 易失：不落库，仅当次运行
}
```

**`origin` 的诚实性要求**：`internal` 只用于**来源可验证**的系统内部通知。
凡是 AI 推断出来的东西，**不能**标成 `internal` 冒充事实 —— 那属于 `text` 里的陈述。

## 4. 工具契约

```ts
interface ToolDef {
  readonly name: string;          // 全局唯一；插件用自家短名做前缀（'qq_'）
  readonly description: string;   // 参数、行为、回执长什么样
  readonly input: JsonSchemaLike; // 参数契约（薄 schema 子集）
  readonly endsTurn?: boolean;    // 调用后结束本轮
}
```

**工具名冲突 → 拒绝挂载并报出原因**，不做静默覆盖。

## 5. 水位闸门（本框架最关键的部分）

### 5.1 投递时刻（三条判据取最小）

```
投递时刻 = min( 首件时刻 + maxBatchAgeMs,
                max( 首件时刻 + minBatchAgeMs,
                     末件时刻 + quietGapMs ) )
若待投递事件数 ≥ maxBatchSize → 立即投递
```

语义：**至少攒够下限，最多等到上限，安静下来就提前走。**

默认值（全部外置可调）：

| 参数 | 默认 | 理由 |
|---|---|---|
| `quietGapMs` | 800 | 人类连发消息的自然间隙 |
| `minBatchAgeMs` | 500 | 避免逐条触发模型 |
| `maxBatchAgeMs` | 5000 | 冷清时也保证 5 秒内有一次判断 |
| `maxBatchSize` | 24 | 切批，防单批 prompt 爆炸 |

### 5.2 四种触发模式

| 模式 | 行为 | 默认适用于 |
|---|---|---|
| `preempt` | 抢占：请求取消当前模型轮并立即投递 | 仅"需立即中止"的事件 |
| `flush` | 立即投递，带上全部积压 | 内部事件 |
| `debounce` | 参与合批（走上表三条判据） | **外部事件（默认）** |
| `piggyback` | 只排队，搭下一趟车；不触发计时/计数 | 当前状态快照 |

### 5.3 水位持久化

- `lastDeliveredCursor` **落盘**；重启后补投水位之后的外部事件
- 队列**不落盘**（事件本身已落库，不会丢事实）
- 内部事件仅在当次运行投递

### 5.4 防空转（这是需求里明确点名的）

**批次内容 + 世界状态无实质变化 → 不调模型，复用上次结论。**

实现：对 `hash(批次事件摘要 + 世界状态版本)` 做语义缓存。命中即跳过模型调用。

## 6. 三层决策分工（"混合，不然 AI 会犯错"）

| 层 | 延迟 | 决策者 | 职责 |
|---|---|---|---|
| **反射层** | <50ms | 零模型本地规则 | 硬安全（急停/越界）、确定性动作 |
| **策略层** | 100ms~1s | 本地逻辑 + 规则 | 意图 → 闭环控制、多源仲裁 |
| **语义层** | 1~30s | LLM（按批喂） | 理解"发生了什么"、决定"要不要做" |

**典型案例「向前走同时不撞墙」**：
- 语义层给意图（"向前走"）
- **策略层保闭环**（向前 + 距离 <0.3m 停）
- 反射层兜底急停
- → AI 无需逐步规划避障；**AI 犯错也不会撞墙**，因为闭环在本地

## 7. 插件契约（npm 包）

```jsonc
{
  "name": "anyentity-world-xxx",
  "type": "module",
  "keywords": ["anyentity-world"],
  "anyentity": {
    "kind": "world",   // world | provider | memory
    "api": 1           // 契约版本；与框架期望值不等则不加载
  }
}
```

- **版本按 kind 独立递增**：World 的不兼容变更只加 world 版本，不牵连 provider
- 插件通过 `anyentity/<路径>` 导入框架，拿到**同一份模块实例**
- 与内建 id 冲突的插件不加载；两个插件同名只加载第一个
- 单个插件失败**不影响**其他插件，原因写入加载记录
